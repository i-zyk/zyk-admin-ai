# 登录与注册需求

## 1. 目标

为当前 Web 应用提供最基本的账号注册、登录和退出功能。用户仅使用用户名和密码注册、登录，登录后进入首页，能够看到自己的用户名。

## 2. 页面

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 登录/注册页 | `/login` | 支持切换登录和注册表单 |
| 登录后首页 | `/dashboard` | 显示用户名和退出登录按钮 |

## 3. 功能需求

### 3.1 注册

- 用户仅填写用户名、密码，均为必填。
- 用户名为 3～20 个字符，仅支持英文字母、数字和下划线；密码至少 8 个字符。
- 用户名忽略大小写且必须唯一，重复注册时提示“用户名已存在”。
- 注册成功后自动登录，并跳转到 `/dashboard`。
- 注册失败时显示明确的错误提示。

### 3.2 登录

- 用户使用用户名和密码登录，均为必填；用户名匹配忽略大小写。
- 登录成功后跳转到 `/dashboard`。
- 用户名或密码错误时，统一提示“用户名或密码错误”。
- 登录状态在刷新页面后保持有效。
- 已登录用户访问 `/login` 时跳转到 `/dashboard`。

### 3.3 退出与访问控制

- 用户点击退出登录后，清除登录状态并跳转到 `/login`。
- 未登录或会话已过期的用户访问 `/dashboard` 时，跳转到 `/login`。
- 受保护接口必须在服务端检查登录状态。

## 4. 基本交互与实现要求

- 输入校验失败时，在表单中显示错误信息。
- 提交期间显示加载状态并禁用提交按钮，避免重复提交。
- 网络异常时显示“网络异常，请稍后重试”，并允许重新提交。
- 复用项目现有 Better Auth、Prisma 和 PostgreSQL 实现认证及数据存储；密码由认证框架安全处理，不以明文保存。
- 本期仅使用用户名密码认证，暂不实现验证码、第三方登录、找回密码和角色权限管理。

## 5. 验收标准

- [ ] 注册和登录表单均只包含用户名、密码两个输入项。
- [ ] 新用户可以使用有效的用户名和密码完成注册，并进入登录后首页。
- [ ] 必填项缺失、用户名格式错误、密码长度不足或用户名重复时，有明确提示。
- [ ] 用户名忽略大小写，大小写不同的同名账号无法重复注册，登录时使用任意大小写均可匹配。
- [ ] 已注册用户可以登录，错误凭据无法登录且有提示。
- [ ] 登录后首页正确显示当前用户的用户名。
- [ ] 刷新页面后登录状态保持有效。
- [ ] 已登录用户访问登录页时进入登录后首页。
- [ ] 退出登录后无法继续访问受保护页面和接口。
- [ ] 未登录或会话过期时，访问受保护页面会进入登录页。
- [ ] 请求失败后可以重新提交，提交期间无法重复提交。
