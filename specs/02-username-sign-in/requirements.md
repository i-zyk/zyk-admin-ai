# R02 用户名登录

> 来源：docs/需求.md 第 2 节「页面」、第 3.2 节「登录」、第 4 节「基本交互与实现要求」

## 背景与目标

现有登录表单使用邮箱 + 密码。本需求把 Web 端登录改为用户名 + 密码，用户名匹配忽略大小写，错误凭据统一提示，登录态在刷新后保持；已登录用户访问 `/login` 时直接进入 `/dashboard`。

## 用户故事

- 作为已注册用户，我希望用用户名和密码登录，且不必记住用户名的大小写，以便顺利进入系统
- 作为已注册用户，我希望刷新页面后仍保持登录，以便不用反复登录
- 作为已登录用户，我希望打开登录页时直接进入首页，以便不会被要求重复登录

## 验收标准

- [✅] R02-AC1：登录表单只包含「用户名」「密码」两个输入项
- [✅] R02-AC2：用户名或密码为空时，在对应输入项下显示必填提示，不发出登录请求
- [✅] R02-AC3：使用正确的用户名和密码登录成功后跳转到 `/dashboard`
- [✅] R02-AC4：用户名以任意大小写输入（如注册为 `Alice`，输入 `ALICE` 或 `alice`）均可登录成功
- [✅] R02-AC5：用户名不存在或密码错误时，统一提示「用户名或密码错误」，不区分具体原因，且不能登录
- [✅] R02-AC6：登录后刷新 `/dashboard` 页面，仍保持登录状态
- [✅] R02-AC7：已登录用户访问 `/login` 时，跳转到 `/dashboard`
- [✅] R02-AC8：提交期间按钮显示加载状态并被禁用，重复点击不会发出多次登录请求
- [✅] R02-AC9：网络异常导致请求失败时，提示「网络异常，请稍后重试」，表单保留输入并可再次提交

## 不在范围内

- 注册相关逻辑（R01）
- 首页内容、退出登录、未登录访问 `/dashboard` 的跳转（R03）
- 「记住我」选项、登录失败次数锁定、验证码
- 移动端登录界面改造

## 依赖

- 依赖 R01 用户名注册（username 插件、数据库字段、错误映射、测试基建）
