# R01 用户名注册

> 来源：docs/需求.md 第 1 节「目标」、第 3.1 节「注册」、第 4 节「基本交互与实现要求」

## 背景与目标

项目现有注册表单使用邮箱 + 姓名 + 密码。本需求把 Web 端注册改为只使用用户名和密码，用户名忽略大小写且唯一，注册成功后自动登录并进入 `/dashboard`。同时搭好后续需求共用的认证基础（Better Auth username 插件、数据库字段与迁移）、表单通用交互（校验提示、加载禁用、网络异常可重试）和自动化测试基建。

## 用户故事

- 作为新用户，我希望只填写用户名和密码就能注册，以便快速开始使用系统
- 作为新用户，我希望输入不合法或用户名被占用时看到明确提示，以便知道如何修改
- 作为新用户，我希望注册成功后直接处于登录状态并进入首页，以便不用再登录一次

## 验收标准

- [✅] R01-AC1：注册表单只包含「用户名」「密码」两个输入项，不再出现邮箱、姓名等字段
- [✅] R01-AC2：输入合法的用户名（3～20 个字符，仅英文字母、数字、下划线）和密码（至少 8 个字符）提交后，账号创建成功、自动登录并跳转到 `/dashboard`
- [✅] R01-AC3：用户名或密码为空时，在对应输入项下显示必填提示，不发出注册请求
- [✅] R01-AC4：用户名长度不在 3～20 或含有字母、数字、下划线以外的字符时，在表单中显示格式错误提示
- [✅] R01-AC5：密码少于 8 个字符时，在表单中显示长度不足提示
- [✅] R01-AC6：用户名已被注册（包括仅大小写不同，如已有 `Alice` 时注册 `alice`）时，提示「用户名已存在」，不创建新账号
- [✅] R01-AC7：服务端同样执行用户名格式、长度和唯一性校验，绕过前端直接调用注册接口也无法写入非法或重复用户名
- [✅] R01-AC8：数据库中不保存明文密码（由 Better Auth 哈希后存储于 `account.password`）
- [✅] R01-AC9：提交期间按钮显示加载状态并被禁用，重复点击不会发出多次注册请求
- [✅] R01-AC10：网络异常导致请求失败时，提示「网络异常，请稍后重试」，表单保留输入并可再次提交
- [✅] R01-AC11：其他注册失败（服务端返回的非上述错误）时，显示明确的错误提示，而不是无提示或英文原始报错

## 不在范围内

- 首页内容、退出登录、访问控制（R03）
- 验证码、第三方登录、找回密码、角色权限管理
- 移动端（`apps/native`）注册/登录界面的改造

## 待确认问题

无。以下事项已于 2026-10-29 与用户确认：

- 测试框架：`apps/server` 用 Vitest 做接口集成测试，`apps/web` 用 Playwright 做 E2E。
- 数据库：Docker 容器 `wizardly_bell` 中原 `postgres` 库属于其他项目，不使用；新建独立库 `zyk_admin_ai`，`apps/server/.env` 的 `DATABASE_URL` 已指向该库。测试复用此库，使用随机用户名。
- 迁移方式：在 `zyk_admin_ai` 库上用 `pnpm run db:migrate` 生成首个迁移。
- 占位邮箱：服务端生成 `<小写用户名>@users.zyk-admin-ai.invalid`，`name` 取原始用户名。
- 移动端：本期不改 `apps/native`，接受其邮箱注册示例失效。
